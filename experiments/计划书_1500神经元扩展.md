# 计划书：MaleCNS 连接组从 80 神经元扩展到 1500 神经元

> 生成时间：2026-09-15
> 所有数字均来自本机实测基准，非估算。基准脚本见 `experiments/_bench_scale.mjs` 与 `experiments/_bench_health.mjs`。

---

## 0. 结论先行

**技术上完全可行，但有三个会直接翻车的雷。**

| 维度 | 80（现状） | 1500 @60 边/节点 | 判定 |
|---|---|---|---|
| 单帧动力学耗时 | 0.0137 ms | 0.571 ms | ✅ 60fps 余量 ×29，完全够 |
| CEM 训练时长 | ~7 分钟 | ~296 分钟（5 小时） | ⚠️ 需并行 + 后台跑 |
| **下行神经元输出幅值** | **0.310** | **0.028** | ❌ **暴跌 11 倍** |
| **静默神经元占比** | **3.8%** | **46.9%** | ❌ **近一半神经元不工作** |
| 可视化边数 | 1,296 | ~90,000 | ❌ Canvas2D 必崩 |
| 细胞类型数 | 43 | 数百 | ⚠️ 图例条写不下 |

**核心警告**：如果只把 `graph.json` 换成 1500 版本而不做增益重标定，**果蝇会变傻** —— 读出层收到的信号只有原来的 1/11，行为将接近随机漂移。

## 1. 现状基线（实测）

### 1.1 当前图统计

```
节点 80   边 1296   唯一细胞类型 43
平均出度 16.20   平均入度 16.20
入度 min/median/max = 0 / 14 / 40
出度 min/median/max = 2 / 14 / 38

按角色：
  input        n=32   平均入度  4.91   平均出度 10.84
  interneuron  n=32   平均入度 24.41   平均出度 23.25
  output       n=16   平均入度 22.38   平均出度 12.81
```

注意：**入度中位数 14、最大 40，不是重尾分布**。说明这份 80 子图是按"接触强度 top-N"筛选出来的稠密核心，不是随机抽样。放大时必须延续这个筛选策略，否则边数会远低于预期。

### 1.2 当前动力学健康度（1500 帧预热后）

```
饱和率(|a|>0.95) 0.0%   静默率(|a|<0.02) 3.8%
均值 0.026   标准差 0.469   输出层幅值 0.310
```

`DYNAMICS = { iterations: 3, leak: 0.7, gain: 1.4, outputGain: 4.0 }`

### 1.3 关键实现细节（改动前必须理解）

**权重归一化** `connectome.js` 第 67-78 行：

```js
totals[post] += contacts * Math.abs(graph.nodes[pre].sign);
weight = totals[post] ? (contacts * graph.nodes[pre].sign) / totals[post] : 0;
```

每个神经元的**入边权重绝对值之和恒为 1**。这个设计使得总输入幅度守恒，规模变大时**不会爆炸**——这是好事。但也正是它导致信号被稀释（见 2.2）。

**读出层** `policy.js`：`16 → 16(tanh) → 4`，320 参数，零偏置。
动作映射 `moveX = tanh(scores[1]-scores[0])`，`moveY = tanh(scores[3]-scores[2])`。

## 2. 三个雷（按危险程度排序）

### 2.1 雷一：可视化崩溃 —— 工作量最大的一项

`brain_view.js` 第 224-263 行，每帧对每条边执行一次 `beginPath + moveTo + lineTo + stroke`：

- 现状 1,296 条 → 约 3-6 ms/帧，占 60fps 预算（16.7ms）的 20-35%，**已经是主要开销**
- 1500 规模 9 万条 → 约 200-450 ms/帧 → **2-5 fps**

另外 `update()` 第 148 行有一个**每帧 O(E) 的 filter**（现存的隐性 bug）：

```js
const outEdges = this.brain.edges.filter(e => e.pre === spikeIdx);
```

9 万条边时这是**每帧 9 万次遍历 + 数组分配**，产生持续 GC 压力。必须改成预计算邻接表。

### 2.2 雷二：信号稀释 —— 最隐蔽，会让果蝇变傻

实测（合成图，保持相同度分布特征，1500 帧预热）：

| 规模 | 边数 | 饱和% | 静默% | 标准差 | 输出幅值 |
|---|---|---|---|---|---|
| REAL 80 | 1,296 | 0.0 | 3.8 | 0.469 | **0.310** |
| 1500 @16.2 | 24,300 | 0.0 | 32.9 | 0.130 | 0.046 |
| 1500 @30 | 45,000 | 0.0 | 40.9 | 0.126 | 0.038 |
| 1500 @60 | 90,000 | 0.0 | 46.9 | 0.123 | **0.028** |
| 1500 @120 | 180,000 | 0.0 | 50.9 | 0.121 | 0.023 |

**原因**：输入只有 8 通道，只驱动 5% 的神经元；信号要跨越更多层才能到达输出层，而每层归一化都把幅度压回 1，多层累积后到达 DN 时已衰减殆尽。**规模越大衰减越严重**。

**修复方案**：重新标定 `gain`。实测扫描（1500 @60）：

| gain | 饱和% | 静默% | 标准差 | 输出幅值 |
|---|---|---|---|---|
| 1.0 | 0.0 | 69.7 | 0.122 | 0.014 |
| 1.2 | 0.0 | 58.7 | 0.122 | 0.019 |
| **1.4（现状）** | 0.0 | **46.9** | 0.123 | **0.028** |
| **1.8（推荐）** | 0.0 | **0.0** | 0.129 | **0.282** |
| 2.4 | 0.7 | 0.1 | 0.121 | 0.779 |

**gain 1.8 时输出幅值 0.282，接近原 80 规模的 0.310，静默率归零。**

> ⚠️ 该扫描基于合成图。真实子图的输出 DN 是高度互连的 hub，实际最优 gain 会略低。**必须在真实 1500 子图上重新扫描**，不要照抄 1.8。

### 2.3 雷三：训练时长 42 倍

CEM 配置 `runCEM(brain, label, generations = 30, popSize = 48, eliteCount = 8, seedsPerGen = 12)`，
`evaluateCandidate(weights, seeds, brain, maxFrames = 1200)`。

总推演帧数 = 30 × 48 × 12 × 1200 = **2,074 万帧**。

| 规模 | 单帧 | 训练时长（含 1.5× 游戏逻辑） |
|---|---|---|
| 80 | 13.7 μs | 7.1 分钟 |
| 1500 @16.2 | 178 μs | 92 分钟 |
| 1500 @60 | 571 μs | **296 分钟（5 小时）** |
| 1500 @120 | 2448 μs | 1269 分钟（21 小时） |

## 3. 路线选择（决定 90% 的工作量）

### 路线 A：只扩储备池 —— ✅ **推荐**

```
输入层 32（8 通道 × 4）   —— 不变
中间层 32 → 1436          —— 扩大
输出层 16（下行 DN）      —— 不变
读出层 16→16→4 = 320 参数 —— 不变
```

**优点**：读出层维度不变 → CEM 搜索空间不变 → 训练可行性保住；checkpoint 结构兼容（只需重训权重值）；改动面最小。

### 路线 B：全扩 —— ❌ 不推荐

输出层扩到 64 → 读出层变成 `64×64 + 64×4 = 4,352` 维。
**CEM 在 320 维能收敛，在 4,352 维基本必然崩溃**（种群 48 根本覆盖不了）。需要换成 CMA-ES 或梯度方法，等于重写训练管线。

### 路线 C：程序化合成（不拉真实数据）

用度保持的随机图生成 1500 节点快得多，但**项目最大的卖点是"真实 MaleCNS 连接组"**，这么做等于自毁招牌。仅作为数据获取失败时的兜底。

## 4. 分阶段执行计划

### 阶段 0：数据可获取性验证（0.5 天）

**任务 0.1** 获取 MaleCNS v1.0 原始数据

源数据规格：
```
神经元 166,700    有向边 25,582,938    突触 124,177,617    细胞类型 11,691
License CC BY 4.0
```

两个来源：
- 官方：https://male-cns.janelia.org/download/ （需注册拿 token）
- HuggingFace：`Xenova/fruit-fly-simulation` 仓库的 `dist/model.json`，已含全量诱导图（"All annotation rows with non-null superclass, induced graph without an additional edge threshold"）

预计下载 1-2 GB。

**任务 0.2 —— 关键验收：重放出现有 80 子图**

`public/data/connectome/manifest.json` 里记录了精确的采样规则和校验和：

```json
"selection": "4 visual cells per each of 8 named types ranked by direct DN contacts;
              union of top 2 DN targets per type, filled to 16 by contact rank;
              top 32 two-hop bridge cells by minimum incoming/outgoing contact strength;
              all measured internal directed edges retained. Ties by body ID.
              No game outcomes used.",
"graphSha256": "2424c9dd2e44534e600aeda1a9058039b1f22a4bd983284a27adc10b22130719"
```

**必须用这套规则重放 80 子图并比对 `graphSha256`。对得上，才证明数据管线可信。** 这一步不能省 —— 否则放大后的图可能是错的，而错误要到训练完才发现。

### 阶段 1：数据管线（1-2 天）

**任务 1.1** 新建 `tools/build_subgraph.py`（或 `.mjs`），把 manifest 的 selection 规则参数化：

```
n_per_channel: 4 → 16     (8 通道 × 16 = 128 输入细胞)
n_output:      16 → 16    (保持)
n_bridge:      32 → 1356  (two-hop bridge，按 min(in,out) 接触强度排序取 top-K)
总计 128 + 1356 + 16 = 1500
```

**任务 1.2** 边保留策略：保留所有测得的内部有向边（与现有规则一致）。
预期边数落在 **30-60 边/节点**（4.5 万 - 9 万边）。

**任务 1.3** 输出 `public/data/connectome/graph-1500.json` + `manifest-1500.json`，
manifest 必须包含：selection 规则原文、graphSha256、节点/边/突触数、细胞类型数。

**验收标准**
- [ ] 无孤立节点（`入度 + 出度 > 0`）
- [ ] 从任一输入细胞出发 BFS 可达输出层（连通性）
- [ ] 平均度落在 30-60 区间
- [ ] sha256 已记录并归档

### 阶段 2：引擎改造（0.5 天）

**任务 2.1** `connectome.js` 边数据结构扁平化

现在是对象数组 `this.edges[e].pre/.post/.weight`，改成三个 `TypedArray`（`Int32Array pre/post` + `Float64Array weight`）。
现状 `step()` 已经是 O(E) 循环，能用；扁平化预计再快 3-5 倍，给可视化留预算。

**任务 2.2** 预计算 CSR 出边索引（`outEdgeStart[]` / `outEdgeIdx[]`），供可视化直接取用。

**任务 2.3** **消除 `brain_view.js` update() 第 148 行的 O(E) filter**（见 2.1）。

**任务 2.4** **gain 重标定**：在真实 1500 子图上扫描 gain ∈ [1.0, 2.4]，
目标：输出幅值 0.25~0.35 且静默率 < 10%。
把最终值和扫描表写进 `manifest-1500.json`。

**任务 2.5** 过滤入度为 0 的节点（当前 80 图里就已经存在 min 入度 0 的节点）。

### 阶段 3：可视化重构（2-3 天，最大工作量）

**任务 3.1** 边 LOD：按 `|weight|` 和当前活动度分桶，只画 top 2,000-4,000 条；
其余渲染成"区域密度云"（低透明度填充），保留视觉密度感。

**任务 3.2** 静态层缓存：拓扑不变的部分画到离屏 canvas，每帧只重绘节点圆点和高亮边。

**任务 3.3** 节点批量绘制：1,500 个圆点用**一个 `beginPath()` 批量画同色圆**，别逐个 stroke。半径 ≤ 2px。

**任务 3.4** 直方图改造：现在 80 根柱子每根 6px 宽，1500 根会变成每根 0.35px（无意义）。
改成**分箱密度图**（如 60 箱，每箱显示平均活动 + 极值包络）。

**任务 3.5** 图例条改造：43 种类型 → 数百种。
改成按 neuropil / 超类分组，只显示 top 12，其余折叠为 `+N more`；加搜索框。

**任务 3.6** hover 命中检测：现为 O(N) 线性扫描，1500 尚可，但建议加均匀网格索引。

**验收标准**
- [ ] 稳定 ≥ 30 fps
- [ ] Hover 响应 < 16 ms

### 阶段 4：训练与验收（1-2 天，含 5 小时后台跑）

**任务 4.1** CEM 并行化：Web Worker 多线程，或把 `seedsPerGen` 从 12 降到 6。
目标把 5 小时压到 1-2 小时。

**任务 4.2** 重训，产出新 checkpoint。
**checkpoint 必须新增字段**：`graphSha256`、`nodeCount`、`dynamicsGain`，并做兼容检测 —— 图换了但权重没换时要有明确报错，别静默出傻结果。

**任务 4.3** 重跑四组基准（trained / matchedControl / circuitSilenced / idle）
以及拓扑优势。当前 `topologyAdvantagePercent: 3.7075` **统计上不显著**；1500 规模下样本更大，有机会做到显著。

**任务 4.4** UI 文案动态化 —— 至少 15 处硬编码：

`index.html`
- `hero.spec_circuit_val`：`MaleCNS v1.0 (80 cells / 1,296 synapses)`
- `panel.net_sub`：`80 NODES / 1,296 SYNAPSES`
- `panel.rig_input`：`INPUT // 16 DNs READOUT`
- `methods.s2_desc`：`80 neurons and 1,296 synapses solved via...`

`brain_view.js`
- 第 216-218 行：`'INFLOW // 32 SENSORY'` / `'RESERVOIR // 32 BRIDGE'` / `'MOTOR // 16 DNs'`
- 第 415-416 行：`divX1 = histX + 32*step` / `divX2 = histX + 64*step`
- 第 433-435 行：`'SENSORY (32)'` / `'RESERVOIR (32)'` / `'MOTOR (16)'`
- 第 467-479 行：图例 tags 硬编码数组（INFLOW 8 / BRIDGE 8 / MOTOR 12）

**任务 4.5** `createMatchedControlGraph` 复查：
`swapAttempts = edgeCount * 4`，9 万边时是 36 万次尝试，字符串 key 拼接约 144 万次 —— 可接受，但建议改用数值 key（`pre * N + post`）提速。

## 7. 一个必须诚实回答的问题：做了能变强吗？

**大概率不会。**

这个任务的输入是 8 个感知通道，输出是 4 个动作评分。80 个神经元对这种低维任务**已经绰绰有余**，1500 个属于极度过参数化。扩大规模可能带来：

- 更长的时序记忆（储备池容量随 N 增长）
- 拓扑归纳偏置的统计显著性提升（现在 3.7% 不显著）

但也可能因为 CEM 搜索难度上升而**变差**。

**所以请先明确动机**：

- **如果是为了展示性/说服力**（"用了 1500 个真实神经元"）—— 值得做，路线 A 可行，5-8 天。
- **如果是为了让果蝇活得更久**（现在 24.36s）—— 这笔时间花在别处更划算：扩充感知通道（现在只有 8 个）、改进 reward 塑形、或者调 `visionRange` / `approachSpeed` 那些感知常数。
