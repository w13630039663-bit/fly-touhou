### 1.3 方向约定（重要，容易搞错）

`%C` 的递增/递减**取决于 boss 相对玩家的方位角**：

```c
unless (([-9971] >= -1.5707964) && ([-9971] <= 1.5707964)) goto MBossCard1At_428;
    $A = 0;  %C = π + [-9998]/9;      // 玩家在 boss 正面扇区 → 顺时针
    goto _604;
MBossCard1At_428:
    $A = 1;  %C = 0 + [-9998]/9;      // 否则 → 逆时针
```
并且发射循环里：

```c
unless ($A == 0) goto _1904;
    %C = %C - 0.124174f;   // A==0
    goto _2056;
_1904:
    %C = %C + 0.124174f;   // A!=0
```

即 **ZUN 式对称设计**：螺旋旋向按玩家位置翻转。复刻时可用自机位置做同样判断。

## 二、解包流程（可复现）

环境限制说明：本机 bash shim 异常（`dirname/cd/head/tail/grep/cat` 均不可用），因此全部命令通过 Python `subprocess` 调用。

### 2.1 获取工具

```python
# Touhou Toolkit（thtk）v12 —— 含 thdat.exe / thecl.exe
url = 'https://github.com/thpatch/thtk/releases/download/12/thtk-bin-12.zip'
# 解压到 D:\苍蝇\experiments\thtk\thtk-bin-12\
```

### 2.2 列出归档内容

```python
subprocess.run([thdat, '-l', '12', r'...\th12.dat'])
# → 181 个条目；关键：stage01..07.ecl（关卡脚本）、*.msg（对白）、*.anm、*.std
```

### 2.3 提取目标文件

```python
subprocess.run([thdat, '-x', '12', arch,
    'stage02.ecl', 'default.ecl', 'stage01.ecl',
    'st02_00a.msg', 'st02_00b.msg', 'st02_01a.msg',
    'st02_01b.msg', 'st02_02a.msg', 'st02_02b.msg'], cwd=outdir)
```

### 2.4 反汇编 ECL → 可读伪代码

```python
subprocess.run([thecl, '-d', '12', 'stage02.ecl', 'stage02.txt'])
# → 2,886 行；130 个 sub，其中 MBossCard1 / MBossCard1At 即本次目标
```

### 2.5 确认符卡名（关键一步）

`*.msg` 是加密/压缩格式，直接读会乱码；但**符卡名字符串就明文嵌在 ECL 里**（Shift-JIS）：

```
!EN
    ins_437(10, 1800, 500000, "大輪「からかさ後光」");
!HL
    ins_439(12, 1800, 500000, "大輪「ハロウフォゴットンワールド」");
!*
```

`!EN` = Easy/Normal 分支，`!HL` = Hard/Lunatic 分支，`!*` = 分支结束。**这就唯一锁定了 sub 与符卡的对应关系。**

> 关于指令符号表：thtk 的 `-m eclmap` 能把 `ins_437` 翻译成 `etNew` 之类的可读名，但 thpatch 的符号仓库（`thpatch/Symbols`）已是**空仓库**（size 0，最后更新 2017），thcrap 发布包里也不含 `.eclm`。因此本报告采用 **"ECL 数值 + 实机帧反推"交叉验证**来确认语义，而非依赖符号表。

### 3.1 `MBossCard1`（符卡主控：声明 + 主循环）

```c
void MBossCard1()
{
    var A, B, C, D;
    ins_413();                                  // 进入符卡
    ins_21(); ins_425(); ins_423();
    ins_256("Ecl_EtBreak", 0.0f, 0.0f, 9999, 0, 0);
    ins_529(0); ins_445();
    ins_416(28);
    ins_304(0.0f, 0.0f);
    ins_305(0, 0, 0.0f, 0.0f);
    ins_301(0, 0, 0.0f, 0.0f);
    [-9949] = 0; [-9948] = 0;
    ins_414(0, 0, 1800, "MBossDead");           // 1800 帧后判定失败
    ins_421(0, "MBossEscape");
!EN
    ins_437(10, 1800, 500000, "大輪「からかさ後光」");
!HL
    ins_439(12, 1800, 500000, "大輪「ハロウフォゴットンワールド」");
!*
    ins_424(43);                                // 符卡背景 / ANM 编号
    ins_301(60, 4, 0.0f, 128.0f);               // boss 移动到发射位
+60: //60
    ins_263(0, 119);
    ins_404(0.0f, 112.0f, 280.0f, 50.0f);
+60: //120
    ins_0();
    goto MBossCard1_832 @ 120;
MBossCard1_728:
    @MBossCard1At() async;      // ← 发射一波（112 帧），async 不阻塞
    ins_83(160);                // ← 等 160 帧
    ins_312(60, 4, 3.0f);       // ← boss 移动
    ins_83(58);                 // ← 等 58 帧
MBossCard1_832:
    if 1 goto MBossCard1_728 @ 120;   // 无限循环
    goto MBossCard1_920 @ 120;
MBossCard1_900:
    ins_83(1000);
MBossCard1_920:
    if 1 goto MBossCard1_900 @ 120;
    return;
}
```

**周期推导（关键）**：`MBossCard1At` 是 `async`，它与后续的 `ins_83(160)` **并行**执行，所以

```
周期 = 160 + 58 = 218 帧，而不是 112 + 218
```

## 四、交叉验证证据（ECL ↔ 实机画面）

从 `QQ20260914-231559.gif`（812×948，GIF89a，211 帧）逐帧分析得到：

### 4.1 坐标标定

```
GIF 812×948  →  aspect 0.85654
游戏 playfield 384×448 → aspect 0.85714
```
**比例吻合（差 0.07%）→ GIF 就是 playfield 的等比放大 ×2.1146**，可直接换算。

### 4.2 角增量验证 ✓

对 177 颗白珠（连通域 + 紫环判据提取）做极坐标分析，**同一条链上相邻珠子的角差**：

```
6.63°  7.44°  7.64°  7.91°  7.24°  6.98°…
```

ECL 值：`0.121767 rad = 6.9764°`（HL 分支，GIF 为 HARD 录像）

**误差 < 2%。** 这是最强证据 —— 每帧发一颗 + 该角增量，唯一解释。

### 4.3 周期验证 ✓

| 来源 | 数值 |
|---|---|
| ECL | 218 帧 = **3.633 s** |
| GIF 实测（面积自相关半周期 1.87s × 2） | **3.74 s** |
| 误差 | **2.9%** |

### 4.4 螺距验证 ✓

| 来源 | 数值 |
|---|---|
| ECL 推导 v·2π/ω | 38.77 px(游戏) = **82.0 px(GIF)** |
| GIF 实测（固定方向的径向亮度峰值间隔） | **85 ~ 93 px(GIF)** |

**命中。** 同时这条证据**反向排除了 `ins_524` 是速度**：若是速度且按 128→17 递减，螺距必然是非均匀变化的，而实测螺距恒定。

## 五、未 100% 确认的项（诚实标注）

| 项 | 现状 | 影响 |
|---|---|---|
| `ins_502(0, 5, 4)` 语义 | 判为 **5 ways（多臂）**，依据是 θ-r 散点图呈多条平行斜线 + 同半径处存在多个角位置的珠子 | 决定"1 条链"还是"5 条链"，**总弹量差 5 倍** |
| `ins_524(0, %B)` 语义 | **不是速度**（已证）。候选：子弹初始半径 / 行为参数 / ANM 索引。B: 128→17 线性递减 | 影响中心区域形态，对整体螺旋外观影响小 |
| `ins_509` 的 11 个行为链 | 判为 th12 的「子弹多段行为」（类型 flag：4 / 2048 / 4096 / 16777216） | 影响子弹的加速、转向、分裂 |
| 符卡背景 `ins_424(43)` | 未解 | 仅影响视觉背景 |

**要彻底解掉这些，唯一途径是找到 th12 的 `.eclm` 符号表**（thpatch 的 `Symbols` 仓库已废弃，需从 thcrap 更新服务器抓取，本次未攻克）。但对**复刻观感**而言，上表 1.1 节的核心参数已足够。

## 六、复刻建议

1. **直接照抄 1.2 节的画布参数**（460×580）。
2. **发射模型**建议改成**真实物理**而非"沿螺旋几何滑动"：
   ```
   每帧：k++；
        angle = θ0 ± k × 0.124174;
        for (a of 5 arms) spawnBullet(bossX, bossY, angle + a×72°, speed);
   ```
   子弹**沿固定方向直线飞出**，螺旋形态是"不同时刻不同角度的直线弹"自然排列出的包络。
3. **旋向按自机方位翻转**（见 1.3 节），这是原作手感的一部分。
4. **波节奏**：
   ```
   波开始 → 连续 112 帧发射（每帧 1 次 × 5 颗）
          → 等 160 帧 → boss 移动 → 等 58 帧 → 下一波
   ```
5. **不要改弹速**。0.766 px/帧 属于东方里**最慢档**（常见 1~5 px/帧），这正是这张符卡的核心手感。
