> **概念澄清（易混淆，务必区分）**
> - 「**3 组重连网络**」= 3 个**不同拓扑的对照组**（`createMatchedControlGraph` 用 3 个不同 seed）→ 这是本次要新增的
> - 「**3 组测试种子**」= 复测现有 checkpoint 时换了 3 套评测种子（80001+/90001+/70001+）→ 这是**背景里的验证手段**，不是要写进训练代码的东西
> - 两者的作用不同：前者降低「单个对照网络的偶然性」，后者检测「结论对评测种子的敏感性」

## 背景

现有 `train.js` 的双轨对决（生物连接组 vs. Matched Control）只有**单组重连样本**，且**未做统计检验**，导致上报的 `topologyAdvantagePercent` 结论不可靠。

### 已实测的问题（**请直接采信，不要重新实验推翻**）

用三组独立测试种子（每组 20 个）复测现有 checkpoint，结果**正负翻转**：

| 测试种子组 | 生物连接组 | 随机重连网络 | 差异 |
|---|---|---|---|
| 80001+ | 1461.5 帧 | 1409.3 帧 | **+3.71%** |
| 90001+ | 1518.0 帧 | 1575.1 帧 | **−3.62%** |
| 70001+ | 1480.9 帧 | 1482.8 帧 | **−0.13%** |

配对 t 检验（n = 60）：平均差异 **−2.2 帧**，**t = −0.053，p ≈ 0.958**

**结论：生物拓扑与随机重连网络在统计上无显著差异。**

这与 flydino 作者自己的声明一致——"证明了学习控制和对电路活动的依赖，而非生物拓扑的优越性"。

因此：
- **`+3.71%` 这个数字不应作为"优势"上报**（它是单个对照网络的偶然结果）
- 必须在产物中如实输出均值 ± 标准差 + p 值

### 3.2 新增统计工具函数

在 `train.js` 中新增（零依赖，纯手写）：

```js
/** 均值 ± 标准差 */
function meanStd(arr) {
  const n = arr.length;
  if (n === 0) return { mean: 0, std: 0, n: 0 };
  const mean = arr.reduce((a, b) => a + b, 0) / n;
  const variance = arr.reduce((a, b) => a + (b - mean) ** 2, 0) / Math.max(1, n - 1);
  return { mean, std: Math.sqrt(variance), n };
}

/** 配对样本双尾 t 检验，返回 { t, df, p } */
function pairedTTest(a, b) {
  // a、b 必须等长，a[i] 与 b[i] 是同一测试种子的配对观测
  const n = a.length;
  if (n < 2) return { t: NaN, df: 0, p: NaN };
  const d = a.map((v, i) => v - b[i]);
  const dMean = d.reduce((x, y) => x + y, 0) / n;
  const dStd = Math.sqrt(d.reduce((x, y) => x + (y - dMean) ** 2, 0) / (n - 1));
  if (dStd === 0) return { t: 0, df: n - 1, p: 1 };
  const t = dMean / (dStd / Math.sqrt(n));
  const df = n - 1;
  return { t, df, p: tDistTwoTailedP(Math.abs(t), df) };
}

/**
 * 双尾 Student-t 分布 p 值 (正则化不完全 Beta 函数，Numerical Recipes 风格连分数实现)
 * 无外部依赖。
 */
function tDistTwoTailedP(t, df) {
  const x = df / (df + t * t);
  return betai(df / 2, 0.5, x);    // P(|T| > t)
}

function gammln(x) {
  const cof = [76.18009172947146, -86.50532032941677, 24.01409824083091,
               -1.231739572450155, 0.1208650973866179e-2, -0.5395239384953e-5];
  let y = x, tmp = x + 5.5;
  tmp -= (x + 0.5) * Math.log(tmp);
  let ser = 1.000000000190015;
  for (let j = 0; j < 6; j++) ser += cof[j] / ++y;
  return -tmp + Math.log(2.5066282746310005 * ser / x);
}

function betacf(a, b, x) {
  const MAXIT = 200, EPS = 3e-12, FPMIN = 1e-300;
  const qab = a + b, qap = a + 1, qam = a - 1;
  let c = 1, d = 1 - qab * x / qap;
  if (Math.abs(d) < FPMIN) d = FPMIN;
  d = 1 / d;
  let h = d;
  for (let m = 1; m <= MAXIT; m++) {
    const m2 = 2 * m;
    let aa = m * (b - m) * x / ((qam + m2) * (a + m2));
    d = 1 + aa * d; if (Math.abs(d) < FPMIN) d = FPMIN;
    c = 1 + aa / c; if (Math.abs(c) < FPMIN) c = FPMIN;
    d = 1 / d; h *= d * c;
    aa = -(a + m) * (qab + m) * x / ((a + m2) * (qap + m2));
    d = 1 + aa * d; if (Math.abs(d) < FPMIN) d = FPMIN;
    c = 1 + aa / c; if (Math.abs(c) < FPMIN) c = FPMIN;
    d = 1 / d;
    const del = d * c; h *= del;
    if (Math.abs(del - 1) < EPS) break;
  }
  return h;
}

function betai(a, b, x) {
  if (x <= 0) return 0;
  if (x >= 1) return 1;
  const bt = Math.exp(gammln(a + b) - gammln(a) - gammln(b) + a * Math.log(x) + b * Math.log(1 - x));
  if (x < (a + 1) / (a + b + 2)) return bt * betacf(a, b, x) / a;
  return 1 - bt * betacf(b, a, 1 - x) / b;
}
```

**验证要求**：实现完后必须自测以下已知值（这是标准 t 分布临界值，可用来验证实现无误）：

| 检验 | t | df | 期望 p（双尾） |
|---|---|---|---|
| 基准 | 2.093 | 19 | ≈ 0.05 |
| 基准 | 2.861 | 19 | ≈ 0.01 |
| 基准 | 1.0 | 59 | ≈ 0.32 |

若自测结果偏差超过 0.005，说明实现有误，必须修正后再继续。

### 3.4.1 关于 3 组的统计效力（重要，必须理解）

**3 组是用户拍板的最终方案**，用于在「统计可信」与「训练时长」之间取平衡（总时长约 50 分钟）。

需要注意的统计事实：

- 这里的 **n（样本量）判定以"配对观测数"为准 = 20 个测试种子**，而非对照组数量 3。因为 `pairedTTest(bioRes.perSeed, ctrlPooledPerSeed)` 是把「同一测试种子上，生物组帧数 vs 3 组对照的均值帧数」作为配对。
- **3 组的作用是降低"单个对照网络的偶然性"**：单组时 `+3.71%`（seed=42）在换种子后翻转为 `−3.62%`；取 3 组池化后，这个抖动会被平均掉，得到的结论更稳。
- 但 **3 组不能提高 n**。若想进一步提升统计效力，只能增加**测试种子数**（当前 20 个），而不是对照组数量。

**因此输出里必须同时给出两个层次的信息：**

1. **组间分布**：3 组对照各自的均值 ± 标准差（看抖动范围）
2. **配对检验**：生物 vs 3 组池化的 t / df / p（看显著性）

**结论措辞要求**：
- 若 p ≥ 0.05 → 写「**无统计显著差异**」，并**不要**把 `topologyAdvantagePercent` 说成"优势"
- 若 p < 0.05 → 写「**存在统计显著差异**」，同时说明 3 组样本量下的结论强度弱于 5 组以上
- 无论哪种结果，都必须如实标注这是 3 组对照下的结论

**禁止**：把 3 组池化的 p 值包装成"经多组验证的强证据"。3 组的定位是**稳健性检查**，不是大样本统计推断。

- ❌ **不要粉饰结论**。若 p ≥ 0.05，必须如实写「无显著差异」。这是这个项目的核心科学价值所在——阴性结果不是失败，是发现。
- ❌ 不要为了省时间只训练 1 组重连然后复制成多组
- ❌ 不要用 `Math.random()` 做任何统计相关的采样
- ❌ 不要引入 npm 依赖（保持零依赖，t 分布自己实现）
- ❌ 不要修改动力学公式、感知公式、适应度公式
- ❌ 不要删掉现有的任何基线（silenced / idle / drift / random）

## 预期产出

跑完一轮后，你会得到：

1. **终端完整对照表**（含均值 ± 标准差 + p 值 + 显著性标记）
2. **更新后的 `public/data/checkpoint.json`**（含 `statistics` 字段与前瞻性声明）
3. **如实结论**：生物拓扑 vs 随机重连是否显著

如果结论是「无显著差异」——**照实写**。这个项目最有价值的科学发现，恰恰是它诚实地报告了阴性结果，而不是为了叙事好看而夸大 `+3.71%`。

## 附：为什么这件事重要

现有 checkpoint 里 `topologyAdvantagePercent: 3.71` 是**单次抽样**。用三组独立种子复测后：

| 组 | 结果 |
|---|---|
| 80001+ | **+3.71%** |
| 90001+ | **−3.62%** |
| 70001+ | **−0.13%** |

符号翻转 = 这个数字是**噪声**，不是信号。加统计检验后，读者能自己判断结论强度，这比任何漂亮数字都可信。

这与 flydino 作者的立场完全一致：

> 证明了学习控制和对电路活动的依赖，而非生物拓扑的优越性。

**能把阴性结果讲清楚的项目，才是严谨的项目。**
