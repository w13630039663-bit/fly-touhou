## 0. 目标环境（重要！必须先对齐坐标系）

Fly-Touhou 的游戏画布：**460 × 580**（`index.html` 中 `#gameCanvas`）。

原 GIF 的游戏区约 **780 × 810**。所以换算分两步：

```
步骤1  GIF 坐标 → 东方标准游戏区(384×448)
      k1 = 384 / 780 = 0.4923

步骤2  东方标准游戏区(384×448) → Fly-Touhou 画布(460×580)
      k2x = 460 / 384 = 1.1979   (横向)
      k2y = 580 / 448 = 1.2946   (纵向)

合并：GIF → Fly-Touhou
      Kx = 0.4923 × 1.1979 = 0.5898
      Ky = 0.4923 × 1.2946 = 0.6373
```

**为简化，下文所有「画布坐标」均已按上式换算完毕，AI 直接用即可。**

## 2. 推测值的推导依据（供参考，可调整）

### 2.1 螺旋转速 ⚠️

**原 GIF 无法测量**（帧率仅 ~10.5fps，帧间角位移混叠）。

**推荐值来源**：东方星莲船中「大轮」型符卡的螺旋臂转速普遍在 **90°~180°/s** 区间。取中值：

```
rotationSpeed = 120 °/s   →  1 圈 / 3 秒
```

**与周期的一致性检验**：符卡周期 3.74s，转速 120°/s → 一个周期内螺旋转 **1.25 圈**。这符合"螺旋臂旋转并向外抛射、周期性重置"的视觉结构。

**如果 AI 想调手感**：速度越快视觉上越"卷"，越慢越"舒展"。建议在 **90~150°/s** 之间调。

### 2.2 发射间隔 ⚠️

**推导逻辑**（从实测的 A(t) 曲线反推）：

链像素面积 A(t) 的上升段约 **12~20 帧**（1.2~2.0 秒）。一个上升段 = 螺旋从中心"吐"出一批珠子并扩到最大。若每轮吐出 **6 颗**（每臂 1 颗），且上升段约 13 帧：

```
fireInterval = 13 帧 / 60fps ≈ 0.22 s
```

**注意**：这是**上界估计**。真实值可能更快（因为 A(t) 混合了"生成"与"离场"两个过程）。建议 AI 从 **0.15~0.25 s** 区间试。

### 2.3 下落幕速度的可靠性说明

**这是本次唯一"方向自洽"的实测值**，可信度较高：

- 块匹配测得 **vx ≈ 0**（无水平漂移）
- **vy > 0**（向下）
- 方向完全符合"下落幕"的物理预期 ✓

换算：`104 px/s (GIF) × 0.5898 = 61.3 px/s`（横纵向缩放差异在此可忽略）

## 4. 结构与配色

### 4.1 三层结构（自底向上）

```
第 4 层  HUD          →  顶部：难度标签 / Bonus / History
第 3 层  外围下落幕    →  青绿(#40e0c0) + 黄白(#ffe060) 小弹，向下缓慢流动
第 2 层  中心螺旋      →  6 条白色(#ffffff)珠链，紫边(#c060e0)
第 1 层  背景          →  暗红螺旋纹 + 中心白色光晕
```

### 4.2 螺旋的几何生成（伪代码）

```
for 每条臂 i in [0, 6):
    baseAngle_i = i * (2π / 6)

每帧：
    修正基准角 phase += rotationSpeed * dt
    for 每条臂 i:
        θ_start = baseAngle_i + phase
        在半径 r 处生成珠子，满足：
            θ(r) = θ_start + k * r        // k 决定"卷"的程度
        每 fireInterval 秒，在当前最大半径处新增一圈
```

**关于 `k`（螺旋紧密度）**：由实测圈间距反推。若每绕一圈半径增加 `armSpacing`：

```
k = 2π / armSpacing = 2π / 12.4 ≈ 0.507 rad/px
```

## 6. 给 AI 的实现要求（建议一并附上）

1. **必须基于实测值**：`arms=6`、`armSpacing=12.4`、`cycleTime=3.74`、`fall.speed=61` 这四项是**实打实测出来的**，不要凭感觉改。
2. **推测值可调**：`rotationSpeed` 与 `fireInterval` 是推测的，如果试跑后视觉不像，优先调这两个。
3. **坐标系必须用 460×580**：不要直接用 GIF 的原始像素值（那是 780×810 的）。
4. **速度单位统一**：`danmaku.js` 里的子弹用的是 `vx/vy`（px/帧），注意 `fall.speed=61 px/s` 要除以 60 转成 **1.02 px/帧**。
5. **可参考现有符卡 0 的代码结构**：`src/game/danmaku.js` 第 361-378 行已有"环状扩散"实现，螺旋可在此基础上改为"角度随半径递增"。
6. **不影响可玩性**：这张符卡的弹速本来就极慢（1 px/帧），复刻后请确认果蝇 AI 仍能反应过来——如果太简单，可以缩短 `fireInterval` 提高密度，而不是加快弹速（加快弹速会破坏原符卡的手感特征）。
