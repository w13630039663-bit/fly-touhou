# 任务书：为 02 连接组卡片补充信息层（方案 A）

## 背景

当前页面 `index.html` 的 **02 / CONNECTOME // MALECNS V1.0 GRAPH** 卡片存在明显留白问题，需要填充信息层，提升科研叙事的说服力。

### 问题根因（已实测确认，请勿重新推导）

| 项目 | 数值 | 说明 |
|---|---|---|
| 卡片容器宽 | 约 528px | `grid-template-columns: 490px 1fr 1fr`，gap 18px，总宽 measure=1600px |
| 卡片容器高 | 350px | `grid-template-rows: 350px 330px` |
| 减 `--panel-head` (42px) |  | `index.html` 第 36 行 |
| 减 `--panel-foot` (40px) |  | `index.html` 第 37 行 |
| **净内容区** | **约 528 × 268px** | `.panel-content` 实际可用空间 |
| 画布声明尺寸 | **480 × 320** | `index.html` 第 944 行 `width="480" height="320"` |
| **冲突** | 画布高 320 > 净高 268 | 画布被压缩，左右各空出约 63px |

### 二次留白来源（关键）

`src/visualizer/brain_view.js` 第 51-63 行，`layoutNodes()` 末尾对坐标又做了一次收缩：

```js
const scaleX = 0.68;
const scaleY = 0.66;
const centerX = 0.50;
const centerY = 0.52;

this.brain.nodes.forEach(n => {
  const rawX = (typeof n.layoutX === 'number' && Number.isFinite(n.layoutX)) ? n.layoutX : 0.48;
  const rawY = (typeof n.layoutY === 'number' && Number.isFinite(n.layoutY)) ? n.layoutY : 0.50;
  n.layoutX = centerX + (rawX - 0.48) * scaleX;
  n.layoutY = centerY + (rawY - 0.50) * scaleY;
});
```

**这 0.68 / 0.66 的收缩是人为制造的留白**，叠加画布压缩后，图形只占了卡片中心一小块。

## 改动 1：底部细胞类型图例条

### 位置

卡片底部，`.panel-content` 内部的最下方。

### 布局建议

**做法**：在 `brain_view.js` 的 `render()` 中，把「可绘制区域」从整个画布改为 `画布上方 78%`，底部 `22%` 用于图例条（背景 `#131620` + 顶部 1px 分隔线 `rgba(255,255,255,0.04)`）。

### 图例内容（三行，等宽字体 9-10px）

```
INFLOW    LC4 · LC11 · LC9 · LC15 · LC16 · LC17 · LC21 · LPLC2
BRIDGE    PVLP151 · PVLP122 · PVLP015 · PVLP011 · DNp103 · LT61b · AVLP079 · CB3400 · +16 more
MOTOR     DNp01 · DNp02 · DNp03 · DNp04 · DNp06 · DNp09 · DNp11 · DNp27 · DNp35 · DNg40 · DNpe052 · pIP1
```

**注意**：
- INFLOW 行完整列出 8 个通道名（每种 4 个细胞，但名称只有 8 个）
- BRIDGE 行列出前 8 种，末尾加 `+16 more`（因共 24 种，避免图例过长）
- MOTOR 行完整列出 12 种

### hover 高亮交互（核心）

1. 图例中每个细胞名是一个可交互的文本元素
2. 鼠标 hover 到某个细胞名（如 `LC4`）时：
   - 网络图中**所有 `type === 'LC4'` 的节点**半径放大 1.6 倍
   - 描边变为 `#4ade80`，线宽 2px
   - 其他节点透明度降低到 0.25
3. 鼠标移出时恢复正常

### 实现约束

- **必须复用现有 canvas**，不要新建 DOM 元素
- 图例文字命中检测：用 `ctx.measureText()` 预先计算每个标签的 `{x, y, width}` 边界框，存入数组，在 `mousemove` 事件里遍历做矩形碰撞检测
- 需要在 `BrainVisualizer` 构造函数中注册 `canvas.addEventListener('mousemove', ...)` 和 `'mouseleave'`
- 新增实例变量 `this.hoveredType = null`

## 改动 2：实时活动直方图

### 位置

卡片右侧或底部图例条上方（若空间不足，可与图例条合并为同一底部区域，直方图在左、图例在右）。

### 内容

绘制 80 个细胞的 `|activity|` 分布：

- 横轴：80 个细胞，按 role 分组排列（32 input → 32 interneuron → 16 output）
- 纵轴：`Math.abs(node.activity)`，值域 `[0, 1]`
- **颜色编码按符号区分**（对齐 flydino 官方口径，Green + / orange −）：
  - `activity >= 0` → `#4ade80`（绿）
  - `activity < 0` → `#f97316`（橙）
- 柱宽：`可用宽度 / 80 - 1`（留 1px 间隙）

### 分组分隔线

在 input/interneuron、interneuron/output 交界处画 2 条竖线（`rgba(255,255,255,0.08)`），并在下方加小标签：

```
SENSORY (32)     |     RESERVOIR (32)     |     MOTOR (16)
```

### 数据来源

直接从 `this.brain.nodes` 读取，每个节点已有 `activity` 字段（`connectome.js` 第 154 行同步）。

### 注意

- **必须过滤非有限值**：`Number.isFinite(node.activity)`，否则画布会出现 NaN 导致的渲染异常
- 这 80 个值应来自**真实动力学输出**，不得另算一套（参考官方声明 "the exact states that feed the action decoder"）

## 改动 3（配套）：修正卡片标题的边数口径

### 位置

`index.html` 第 941 行：

```html
<small data-i18n="panel.net_sub">80 NODES / 1,296 SYNAPSES</small>
```

### 问题

`brain_view.js` 第 151 行的渲染循环是：

```js
for (let i = 0; i < this.brain.edges.length; i += 2) {
```

**只画了偶数索引的边（648 条）**，但标题标称 1,296。这是性能优化（合理），但口径不一致。

### 修法（二选一）

- **选项 A**：改为全量渲染（去掉 `i += 2`）。648 条 → 1296 条线在 480×320 画布上性能可接受，视觉更密实
- **选项 B**：保留 `i += 2`，标题改为 `80 NODES / 1,296 SYNAPSES (648 RENDERED)`

**推荐选项 A**，因为方案 A 本身就是要"填满留白"，全量渲染能让网络图视觉更饱满。

## 改动 4（可选）：调整 layoutNodes 收缩比例

若完成上述改动后仍显空旷，可将 `brain_view.js` 第 52-55 行：

```js
const scaleX = 0.68;
const scaleY = 0.66;
const centerX = 0.50;
const centerY = 0.52;
```

调整为：

```js
const scaleX = 0.82;
```

**理由**：底部要腾出 22% 给图例条，所以图形本身应向上移（centerY 从 0.52 → 0.46）、并横向铺开（scaleX 0.68 → 0.82）。

**配合调整**：`index.html` 第 944 行画布尺寸建议改为 `width="520" height="300"`，更贴合净内容区比例。

## 参考：官方口径（flydino.cobanov.dev）

> Colored cells use the exact states that feed the action decoder. Gray atlas cells are unmodeled context.
>
> Computed activity is dimensionless, not measured spikes or membrane voltage.

即：**着色必须用喂给动作解码器的同一批状态值；活动值是无量纲的，不是放电率、不是膜电位。** 文案措辞请与之一致，避免使用 "spike" / "firing rate" / "membrane potential" 等词。
