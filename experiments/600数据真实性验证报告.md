## 3. 发现的 4 处瑕疵（诚实汇报）

### 3.1 `checkpoint600a.json` 内部自相矛盾 ⚠️ 建议修

同一个文件里：

```json
"topologyAdvantageSignificant": true,          ← 声称"拓扑优势显著"
"topologyAdvantageAdjustedP": 0.0403,
"controlIntegrity": "INVALID — 修复前 train.js 产出…matchedControl/topologyAdvantage* 不可引用"  ← 又说"不可引用"
```

而且它的对照只有 **1 组**（seed 42），却照写了"Bonferroni 校正"——单组时校正系数 = 1，
等于**没做校正**。这恰好违反项目自己定的纪律：
> "冒烟时就抓到 1 代下 control 偶然'显著胜出'，多组对照必须校正，否则 p 值虚高。"

**影响评估**：该字段**不被 UI 消费**（全项目搜索确认只在 `train.js` 写入 + JSON 存储），
且 A 案的主判据是"vs 旧 v600 的独立测试配对比较"（Δ=+302.6f），**不依赖这个字段**，所以结论不受影响。
**建议**：把 `topologyAdvantageSignificant` 置为 `null` 或加 `invalid: true`，与 `controlIntegrity` 保持一致。

### 3.2 `checkpoint600.json` 缺 `controlIntegrity` 字段

HANDOVER 文档称"checkpoint600 与 600a/b 的 matchedControl/topologyAdvantage 字段**均标注 INVALID**"，
但实际 `checkpoint600.json` 的 `controlIntegrity` 是 `null`（没有该字段）。
它的 `topologyAdvantageNote` 已明确写"不可作为优越性证据"、`topologyAdvantageSignificant` 也已正确置 `false`，
所以实质上是诚实的，只是**文档与实物有措辞出入**。

### 3.3 `manifest600.json` 不是构建脚本的原始输出

`build_graph_600.py` 写出的 manifest 里**没有** `roster` 字段，但实际文件有
（19:15 被后续脚本追加）。这不影响正确性（`graphSha256` 仍然正确、可验证），
但如果有人拿"重放脚本 → 对比 manifest 全文"来验证，会得到"不一致"的假警报。

### 3.4 v1 声明的一个源哈希无法在本机验证

v1 的 `manifest.json` 声明 edges 源为 `e35da783…`（当年用的**全量** weights），
而本机只存了 `9b3beab1…`（**traced-only**）。这份文件不在本地，故无法直接验证。
**但**：v1 的 1296 条边已用 traced-only 源完整交叉核对（逐边接触数 1296/1296 一致），
说明 v1 图本身可信。属于"档案不全"而非"数据有问题"。

### 附：口径差异（非瑕疵，说明一下）

复现"胜 18/20"时我得到 17/20（严格 `>`）。定位原因是 **seed 80018 双方都跑到 1800 帧上限（平局）**，
用 `>=` 计为胜即 18/20。平均 Δ=302.55f 与记录的 +302.6f 完全一致。
p 值我用 B=20000（与 `train.js` 同参）得 0.0039、记录 0.0046，属 bootstrap 重采样实现细节差异，量级一致。

## 6. 结论与建议

### 结论

1. **数据是真的**：真实 MaleCNS v1.0 诱导子图，血统可逐环验证，构建可位级复现。
2. **成绩是真的**：7 个 checkpoint 的记录成绩全部能用保存的权重精确重跑（Δ=0.00f）。
3. **负结果也是真的**：600 比 80 差 20%（−20.0%，p=0.0065）这个反直觉结论**不是造假**，
   而且它的机制已被定位（per-post 归一化导致 DN 读出信号稀释），并被 A 案反转（1538.2f）。
   这一"发现→归因→修复→复现"的链条本身就说明工作是真做的。
